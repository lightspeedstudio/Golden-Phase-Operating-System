reply from source port 67. The board's DHCP/DNS code was correct all along.

## 2. USB HID host — from scope to first light

- **Research** — established it's a **host** port (USB3320 → Type-A `J10`), the Xilinx driver is
  device-mode (wrong role), and there's no `smoltcp`-equivalent for USB host → weeks of work,
  tractable via TinyUSB. Then mined the vendor packs and found the **exact grounded register
  values** (device tree + `1_hello_world` `ps7_init` + `xusbps_hw.h`).
- **U0 brain** (`746a4a3`) — un-gated the phase state-domain VM std→baremetal and added
  `DomainId::Usb` (10-state lifecycle as phase words over Kairos0–3).
- **U0 muscle** (`d5d1857`) — `usb.rs` host bring-up from grounded values + `usb probe`.
- **U0 PROVEN** (`16ed781`) — first hardware try:
  ```
  usb0: host up @ 0xE0002000 (ULPI) -- device CONNECTED, full-speed, reset done
  usb: phase lifecycle -> powered -> connected -> reset (recorded in statechain, domain=usb)
  state domains → usb states=10 word_len=2
  ```

Reference: [BAREMETAL_USB.md](BAREMETAL_USB.md).

## 3. The method that made both possible

**Read the vendor's own files → write the no_std Rust → prove on real silicon → commit with
evidence.** Ethernet used lwIP → smoltcp; USB used the vendor `ps7_init`/device tree → `usb.rs`.
And the **border pattern** held again: foreign hardware below (`gem.rs`, `usb.rs`), the
Golden-Phase world above (PhaseNet, the USB state domain). USB is the same shape one layer down.
