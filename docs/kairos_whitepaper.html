KairOS Whitepaper

KairOS is a phase-kernel research operating system that treats verified four-state phase algebra as a first-class systems primitive. It combines a hosted runtime, a baremetal RISC-V boot target, authenticated statechain recording, ANOM privacy controls, PhaseLink communication, and a default Parallel Phase Math Engine designed to scale from single-core baremetal to multicore hosts and future accelerators.

Executive Summary

KairOS is designed for environments where runtime behavior, transition legality, and audit visibility matter as much as raw execution. Rather than treating system state as an opaque collection of mutable flags, KairOS models process, memory, storage, communication, and operator actions through a compact verified phase system built on four canonical states: Phi0, Phi1, Phi2, and Phi3.

Around that core, KairOS adds a security and integrity framework that includes a statechain ledger, Merkle-root aggregation, boot-session sealing, public-vs-private state visibility policies, ANOM mode, per-object protection, and PhaseLink proof frames. The result is an operating system research platform that is both introspectable and strict about transition validity.

KairOS is intended to run on single-core baremetal, QEMU, normal desktop CPUs, multicore servers, and future accelerator-attached systems without making special hardware a runtime requirement.

Architecture

1. Canonical Mathematical Authority

The single source of truth for phase behavior remains core/gphase_core.rs. It defines:

  • the four-state alphabet
  • compose behavior
  • reflection behavior
  • left/right grouping topology behavior
  • threshold and energy projections

No optimized backend is allowed to redefine those semantics.

2. Parallel Phase Math Engine

The default Phase Math subsystem sits above the canonical core and below system consumers such as the scheduler, StateClock, proof generation, Merkle batching, and PhaseLink. 

Canonical scalar core
        ↓
Precomputed runtime tables
        ↓
Batch submission interface
        ↓
Worker ownership + bounded lanes
        ↓
Optional backend selection
        ↓
Proof / Merkle / trajectory scheduling

3. Priority Lanes

  • Lane 0: immediate transition decisions
  • Lane 1: trajectory and StateClock work
  • Lane 2: proofs, Merkle updates, and analytics

This allows the scheduler to proceed on the minimal decision path while larger reductions are queued for later processing.

4. Object-Sharded Work Ownership

KairOS uses stable object sharding through: 

worker = object_id % active_worker_count

That preserves per-object ordering while still exposing cross-object parallelism.

5. Storage and Integrity Layout

  • State transitions enter the statechain as per-object events.
  • Subsystem heads roll into Merkle roots.
  • Kernel root aggregation reflects the active trusted system state.
  • PhaseLink maintains its own verified communication-root path.

Security and Trust Model

ANOM and Visibility

KairOS separates true internal state from public visibility. In transparent mode, authorized operators can inspect normal runtime views. In ANOM-protected paths, public output is represented as commitments rather than raw protected phase values.

Per-Object Protection

Selected objects can be protected individually. The implementation preserves object history, statechain participation, Merkle participation, and kernel-internal scheduling access while restricting public disclosure.

Proof and Root Discipline

  • BootSessionRoot binds the current boot life.
  • EquationRoot binds the mathematical authority for proofs and transitions.
  • Statechain events capture transition evidence over time.
  • Merkle roots summarize subsystem integrity.
  • PhaseLink frames quarantine malformed or untrusted external input before acceptance.
KairOS does not treat EquationRoot as a secret key, does not expose ANOM passphrases or object data keys, and does not accept externally supplied PhaseLink frames into trusted state before validation completes.

  • dashboard summarizes authority, roots, topology, object locks, and Phase Math status.
  • watchdog reports statechain audit integrity.
  • root and audit expose root and chain health.
  • checkpoint works with signed checkpoint logic in hosted builds.

Communications

  • phasenet provides a native phase-state networking path.
  • phaselink provides proof-framed byte/phase communication with loopback and simulation.

Performance and Acceleration Controls

  • phaseperf status shows backend, workers, and processed work counts.
  • phaseperf backend scalar forces the canonical reference path.
  • phaseperf queues exposes bounded queue pressure.
  • phaseperf benchmark exercises a representative batch.
  • phaseperf verify confirms scalar equivalence.
  • phi-stability status reports stability benchmark state.

Remote Operations and AI

  • kairos_ssh binary serves Ed25519-authenticated remote shells on port 2222 by default.
  • ssh status, ssh key list, and ssh audit manage keys and sessions.
  • ai connect <host> <port> opens the management-network JSON bridge.
  • ai allow <tool> authorizes tool execution at Phi3 under root authority.
