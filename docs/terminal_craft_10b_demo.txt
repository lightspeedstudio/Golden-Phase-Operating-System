Golden Phase OS — Avenue 10B WP-2 terminal demo transcript (hosted-sim)
========================================================================

Captured by piping commands into the real hosted shell runtime
(`kairos_host`, `--features craft`) and recording its stdout verbatim.
Nothing below is hand-edited or fabricated — this is the actual output
of running the propulsion-stuck FDIR mission over the craft fixture's
`PhaseTransportCraftAdapter`, which drives the real
`phase_transport::TransportController` (M=4 diagonal port lattice,
Φ2 glider packets, send -> tick(arrival) -> verify_trace, auto-ack).

HONESTY NOTE: this is a hosted-simulation scenario. The glider carrier
here is `phase_transport::TransportController` executing entirely in
software over the sealed Avenue 2 glider law — the same law that was
separately verified on iCE40/iCE Max silicon (see fpga/evidence/). This
transcript is not a claim of live-on-silicon execution; it demonstrates
the craft FDIR mission and packet-replay cross-check running the compose
kernel + phase-transport carrier together, hosted.

Capture command:
  export CARGO_TARGET_DIR="$TEMP/kairos-target-wp2"
  printf 'craft init\nscenario run prop-stuck-glider\ncraft status\ncraft quarantine status\nexit\n' \
    | cargo run --bin kairos_host --features craft --quiet

Notes on reading this transcript:
  - `pkt=N` on each mission line is the packet id returned by
    `PhaseTransportCraftAdapter::send`, i.e. the id of the Φ2 glider
    packet that physically carried that command across the M=4 diagonal
    port lattice (kernel/ground=(1,1), navigation=(2,2),
    propulsion=(0,0), power=(3,3)).
  - `pkt=17` (the rejected `prop_fire` attempt while quarantined) shows
    `ack=false` by design — `execute()` only acknowledges commands that
    are actually accepted and delivered; a rejected send is audited but
    never gets a reply packet.
  - "PACKET REPLAY CROSS-CHECK" is produced by
    `kernel::craft::verify_packet_replay`: for every transported packet
    it resolves the matching statechain event by (object, sequence),
    confirms the transported opcode matches the audited operation name
    (or, for the reject path, that the wire opcode's payload hash
    matches the audited "rejected_quarantined_operation" record), checks
    the packet was acknowledged, and recomputes the associator parity.
  - "statechain replay: live == replayed (OK)" is an independent
    confirmation from `CraftController::replay_episode` — state rebuilt
    purely from the hash-chained ledger matches the live controller.
  - "sealed checkpoint" reflects `FdirController::prove` calling
    `StatechainLedger::seal_checkpoint()` after `live == replayed` is
    confirmed inside `prove` itself.
